Map - Словарь где ключом может быть что угодно. В отличие от обычного {} он сохраняет порядок вставки, не имеет проблем с прототипом("_"_proto__.toString) и быстрее при частых вставках и удалениях
```js
const cache = new Map();
cache.set('user:1', { name: 'Alex' });
cache.set(42, 'число как ключ');
cache.get('user:1');
cache.has(42);
cache.delete(42);
cache.size; // 1
for (const [k, v] of cache) { /* ... */ }
```

Set - Коллекция уникальных значений
```js
const ids = new Set([1,2,2,3]) //1,2,3
const unique = [... new Set(arr)]
ids.has(2) // O(1), в отличие от arr.includes()
```

### WeakMap и WeakSet

Главное отличие - **слабые ссылки на ключи**. Если на объект-ключ больше нигде нет ссылок, сборщик мусора его удалит вместе с записью. Из-за этого:

- ключами могут быть только объекты (и несуществующие в реестре символы);
- нет `size`, `keys()`, `forEach` и итерации: содержимое недетерминировано, потому что зависит от момента работы GC.
```ts
const meta = new WeakMap();

function track(req) {
  meta.set(req, { startedAt: Date.now() });
}

function duration(req) {
  return Date.now() - meta.get(req).startedAt;
}
// Когда req уничтожается, запись исчезает сама. Утечки памяти нет.
```
Если бы вы использовали `Map`, то запись держала бы `req` в памяти вечно, пока вы не вызовете `delete` вручную. Это классическая утечка в долгоживущем сервере.
#### WeakSet: пометка объектов

```js
const processed = new WeakSet();

function handle(job) {
  if (processed.has(job)) return;
  processed.add(job);
  // ...
}
```

### Типичные применения в Node.js

- **Кеш результатов вычислений по объекту** (мемоизация) - `WeakMap`, чтобы кеш не раздувался.
- **Метаданные для сокетов, запросов, соединений** без мутации самих объектов - `WeakMap`.
- **Приватные поля в старом стиле** (до `#private`) - `WeakMap`.
- **Защита от повторной обработки или циклов** (обход графа объектов) - `WeakSet`.
- **Кеш по строковому ключу** (id, URL) - только `Map`. `WeakMap` тут не подойдёт, так как строки не могут быть ключами.
- **LRU-кеш** - `Map` (порядок вставки + `delete`/`set` для "освежения").

### Правило выбора

1. Ключи - примитивы или нужна итерация/`size` → **Map/Set**.
2. Ключи - объекты, и данные имеют смысл, только пока объект жив → **WeakMap/WeakSet**.
3. Нужен именно "кеш с TTL" → `Map` + таймеры (или `lru-cache`), а не Weak-коллекции, потому что GC не гарантирует, когда удалит запись.

### Частая ошибка

Ожидать, что `WeakMap` сам "очищается по времени". Он очищается только когда на ключ не осталось ссылок, и момент этого непредсказуем. Для управляемого кеша используйте `Map` с явной политикой вытеснения.
