**Data race** это ситуация, когда две или более горутины **одновременно обращаются к одной и той же ячейке памяти**, причём **хотя бы одно обращение это запись** и **нет синхронизации** между ними.
```go
var counter int
var wg sync.WaitGroup

for i := 0; i < 1000; i++ {
    wg.Add(1)
    go func() {
        defer wg.Done()
        counter++ // чтение, увеличение, запись: не атомарно
    }()
}
wg.Wait()
fmt.Println(counter) // не всегда 1000
```

`counter++` состоит из трёх шагов, и горутины затирают результаты друг друга.

**Последствия:** неверные результаты, повреждённая память (особенно для интерфейсов, строк и слайсов, которые состоят из нескольких слов и могут быть прочитаны «наполовину» записанными), падения, трудновоспроизводимые баги. По модели памяти Go программа с гонкой имеет неопределённое поведение.

### Data race vs race condition

- **Data race**: конкретная техническая проблема доступа к памяти без синхронизации. Находится детектором.
- **Race condition**: логическая ошибка, зависящая от порядка выполнения (например, «проверил баланс, потом списал» без блокировки). Может быть и без data race (всё защищено мьютексами по отдельности, но логика неверна). Детектор такое не находит.

### Как найти: race detector

```bash
go run -race main.go
go test -race ./...
go build -race
```

Пример вывода:

```
WARNING: DATA RACE
Write at 0x00c000012345 by goroutine 8:
  main.main.func1()
      main.go:12 +0x...

Previous write at 0x00c000012345 by goroutine 7:
  main.main.func1()
      main.go:12 +0x...
```

Видно, какие горутины, какие строки и где созданы горутины.

**Особенности:**

- Находит только гонки, которые **реально произошли при запуске**. Нет гонки в этом прогоне, нет и отчёта. Поэтому запускайте на хороших тестах, в том числе нагрузочных.
- Замедляет программу в 2-20 раз и увеличивает потребление памяти в 5-10 раз, поэтому используют в тестах и CI, а в продакшене обычно нет.
- Требует `cgo` (на большинстве платформ).
- Ложных срабатываний нет: если детектор сообщил, гонка настоящая.
- Рекомендуется всегда включать `-race` в CI.

### Как исправлять

```go
// 1. Мьютекс
mu.Lock(); counter++; mu.Unlock()

// 2. Атомарные операции
var counter atomic.Int64
counter.Add(1)

// 3. Каналы: владение данными у одной горутины, остальные общаются с ней сообщениями
```

**Типичные источники гонок:**

- Конкурентный доступ к map (`fatal error: concurrent map writes`).
- Захват переменной цикла в замыкании (до Go 1.22).
- Чтение и запись полей структуры из разных горутин без блокировки.
- Добавление в слайс (`append`) из нескольких горутин.
- Забытая синхронизация флага остановки (`stopped bool`), используйте `atomic.Bool` или канал.
- Копирование структуры с мьютексом.
