map[K]V - это хешь таблица. Ключ должен быть comparable(можно сравнивать), числа, строки, bool, указатели, структуры и массивы из comparable полей. Слайсы maop, и функции не могут использоваться в качестве ключей

Под капотом:
массив бакетов в каждом до 8 пар ключ значение. Ключи хэшируются, младшие биьы выбирает сам бакет, старшие байты хэша хранятся джля быстрого сравнения.
При переполенние испольузесчят цеполчка overflow бакетов. когда коэфициент заполнения превышает определенный порог (примерно 6.5 элементов на бакет) таблица растет обычно в x2 Раза, эвакуация происходит постепенно. с go.1.24 реализация заменненна на swiss table Но внешне поведение тоже 

Map это **ссылочный тип**: при передаче в функцию копируется дескриптор, данные общие.

```go
m := make(map[string]int)     // или map[string]int{}
m["a"] = 1
v, ok := m["b"]               // ok == false, v == 0 (zero value)
delete(m, "a")
```

Идиома "comma ok" нужна, чтобы отличить отсутствующий ключ от ключа с нулевым значением.

## Порядок итерации и потокобезопасность

### Порядок

Порядок итерации по map **не определён и намеренно рандомизируется** (стартовая позиция выбирается случайно при каждом `range`). Это сделано, чтобы разработчики не полагались на порядок.

Нужен стабильный порядок: собрать ключи в слайс, отсортировать, идти по нему.

go

```go
keys := make([]string, 0, len(m))
for k := range m { keys = append(keys, k) }
sort.Strings(keys) // или slices.Sort(keys) с Go 1.21
for _, k := range keys { fmt.Println(k, m[k]) }
```

### Потокобезопасность

Map **не потокобезопасна**. Одновременная запись и чтение (или две записи) из разных горутин это data race. Рантайм часто это детектит и **падает с fatal error** (`concurrent map writes` / `concurrent map read and map write`), который нельзя перехватить через `recover`.

Способы защиты:

```go
// 1. Mutex/RWMutex вокруг map (самый частый и предсказуемый вариант)
type SafeMap struct {
    mu sync.RWMutex
    m  map[string]int
}
func (s *SafeMap) Get(k string) (int, bool) {
    s.mu.RLock()
    defer s.mu.RUnlock()
    v, ok := s.m[k]
    return v, ok
}

// 2. sync.Map
var sm sync.Map
sm.Store("a", 1)
v, ok := sm.Load("a")
```

**`sync.Map`** оптимизирована для двух сценариев: ключ записывается один раз и читается много раз (кэши), либо горутины работают с непересекающимися наборами ключей. В остальных случаях `map + RWMutex` обычно проще и быстрее, к тому же типобезопасна (у `sync.Map` ключи и значения `any`).

Одновременное **только чтение** из нескольких горутин безопасно, если никто не пишет.

Для проверки используют `go run -race` / `go test -race`.


### Коротко для собеседования

- Массив: фиксированный размер, значение, копируется. Слайс: дескриптор (ptr, len, cap) над массивом.
- `append` пишет в тот же массив, пока хватает cap, иначе выделяет новый и копирует.
- Map: хеш-таблица с бакетами, ссылочный тип. Из nil-map читать можно, писать паника.
- Порядок итерации случайный, map не потокобезопасна (нужен `Mutex`/`RWMutex` или `sync.Map`).
