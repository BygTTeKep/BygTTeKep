## когда использовать, значение vs ссылка

### Основы

Указатель хранит **адрес** переменной.

```go
x := 10
p := &x        // p имеет тип *int, хранит адрес x
fmt.Println(*p) // 10, разыменование
*p = 20         // меняем x через указатель
fmt.Println(x)  // 20
```

- `&` берёт адрес, `*` разыменовывает.
- Zero value указателя: `nil`. Разыменование nil вызывает панику.
- **Арифметики указателей нет** (кроме пакета `unsafe`).
- `new(T)` выделяет zero value типа T и возвращает `*T`. Часто пишут `&T{}`.
- Для указателя на структуру `p.Field` работает без явной звёздочки (`(*p).Field` не нужно).
### Всё в Go передаётся по значению

Формально **ссылочной передачи в Go нет**. При вызове функции аргумент всегда копируется. Разница в том, **что именно** копируется:

```go
func setVal(n int)   { n = 100 }   // меняет копию
func setPtr(n *int)  { *n = 100 }  // копия адреса, но указывает на оригинал

a := 1
setVal(a); fmt.Println(a) // 1
setPtr(&a); fmt.Println(a) // 100
```

Типы, которые внутри уже содержат указатель на данные (слайс, map, канал, функция, интерфейс, строка), при копировании делят данные:

```go
func f(s []int, m map[string]int) {
    s[0] = 99        // виден снаружи
    m["a"] = 1       // виден снаружи
    s = append(s, 5) // снаружи НЕ виден (копия len/cap)
}
```

Поэтому для них указатели обычно не нужны. Исключение: нужно, чтобы функция могла **переприсвоить** сам слайс/map (`*[]int`), но чаще просто возвращают новое значение.

### Когда использовать указатель

**Да:**

- **Нужно изменить оригинал** (метод меняет состояние структуры, функция заполняет переданный объект, как `json.Unmarshal(data, &v)`).
- **Большая структура**, копировать дорого.
- **Структура содержит `sync.Mutex`, `sync.WaitGroup`** и т.п.: их копировать нельзя (`go vet` ловит), нужен указатель.
- **Нужно выразить «значения нет»** (`*int` может быть `nil`), например опциональные поля в JSON/БД.
- **Единообразие методов**: если хотя бы один метод типа с pointer receiver, обычно делают все pointer receiver.

**Нет:**

- Маленькие типы (`int`, `bool`, небольшие структуры): копия дешёвая, указатель даже вреднее (лишняя косвенность, нагрузка на GC).
- Слайсы, map, каналы: они уже ссылочной природы.
- Если нужна **неизменяемость**: значение передаёт копию, побочных эффектов нет.
- Не стоит гнаться за указателями «ради производительности» без измерений: значения остаются на стеке и не нагружают GC.

### Value receiver vs pointer receiver

```go
func (u User) Name() string   { return u.name }  // работает с копией
func (u *User) SetName(n string) { u.name = n }  // меняет оригинал
```

Pointer receiver нужен, когда метод меняет состояние, структура большая или содержит мьютекс.

### Escape analysis: стек и куча

Компилятор сам решает, где разместить переменную. Если указатель на локальную переменную «убегает» из функции (возвращается, сохраняется в глобальную), переменная уходит в **кучу**:

```go
func newInt() *int {
    x := 5
    return &x // безопасно в Go, x переедет в кучу
}
```

Это нормально и безопасно (висячих указателей нет, за память отвечает GC), но лишние аллокации в куче нагружают сборщик. Посмотреть решения компилятора: `go build -gcflags="-m"`.

### Ловушки

- **nil-указатель**: разыменование даёт `panic: nil pointer dereference`. Проверяйте перед использованием.
- **Указатель на переменную цикла** (до Go 1.22): все итерации делили одну переменную, поэтому `&v` давал один и тот же адрес. С Go 1.22 у каждой итерации своя переменная.
- **Указатель на элемент слайса** может «устареть» после `append` с реаллокацией: он указывает на старый массив.
- **Указатель на интерфейс** (`*io.Reader`) почти всегда ошибка, интерфейс сам по себе лёгкий.
- **Сравнение указателей** сравнивает адреса, а не содержимое.

### Коротко для собеседования
 Go всё передаётся по значению, указатель просто копирует адрес. Указатели нужны для изменения оригинала, больших структур, типов с мьютексом и для опциональности. Слайсы, map и каналы уже содержат ссылку на данные, поэтому указатель на них обычно не нужен.
