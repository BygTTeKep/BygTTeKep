time.Ticker периодически отправляет текущее время в канал С, через равные интервалы пока его не остановят

```go
ticker := time.NewTicker(time.Second)
defer ticker.Stop()

for {
    select {
    case t := <-ticker.C:
        fmt.Println("tick", t)
    case <-ctx.Done():
        return
    }
}
```

Применение: периодические задачи (опрос, сброс буфера, heartbeat, обновление кэша, метрики).

### Как работает
- `NewTicker(d)` создаёт тикер и канал `C` с буфером на **1 элемент**.
- Рантайм по таймеру кладёт в `C` текущее время каждые `d`.
- Если читатель **не успевает** (обработка дольше интервала), тик **отбрасывается**: канал уже полон, новое значение не блокирует рантайм, а просто пропускается. Очередь тиков не копится, поэтому «догоняющих» срабатываний не будет.
- `d` должен быть больше нуля, иначе паника.
- `ticker.Reset(d)` меняет интервал на лету (Go 1.15+).
- Интервал отсчитывается от моментов тиков, а не от конца обработки, поэтому дрейфа нет. Если нужна пауза именно после обработки, используют `Timer` с `Reset` или `time.Sleep`.
### Чем отличается от `Timer` и `After`

| |`Ticker`|`Timer`|`time.After`|
|---|---|---|---|
|Срабатывание|**многократно**, периодически|**один раз**|**один раз**|
|Что возвращает|`*Ticker` с каналом `C`|`*Timer` с каналом `C`|сразу канал `<-chan Time`|
|Можно остановить|`Stop()`|`Stop()`, `Reset()`|нельзя (нет объекта)|
|Применение|периодические задачи|таймаут, отложенное действие|короткий таймаут в `select`|

```go
timer := time.NewTimer(2 * time.Second)   // один раз через 2с
defer timer.Stop()
select {
case <-timer.C:
    fmt.Println("время вышло")
case res := <-resultCh:
    fmt.Println(res)
}

select {
case res := <-resultCh:
case <-time.After(2 * time.Second):       // то же, но короче
}
```

`time.After(d)` это по сути `time.NewTimer(d).C`: удобная обёртка, но без доступа к самому таймеру, значит его **нельзя остановить**.

Также есть `time.AfterFunc(d, f)`: запускает функцию `f` в отдельной горутине через `d` (возвращает `*Timer`, его можно остановить). И `time.Tick(d)`: обёртка над `NewTicker`, возвращающая только канал, остановить нельзя.

### Почему нужно вызывать `Stop()`

**Ticker** держит ресурсы рантайма: запись в куче таймеров и канал. Пока он не остановлен, рантайм продолжает периодически его обслуживать, а объект остаётся достижим.
- **До Go 1.23** неостановленный тикер **никогда не собирался GC**, даже если на него не осталось ссылок: он оставался в списке таймеров навсегда. Это утечка памяти и лишняя работа рантайма (например, тикер, создаваемый в каждом запросе или в каждой итерации цикла).
- **С Go 1.23** (при `go 1.23` и выше в `go.mod`) неиспользуемые таймеры и тикеры без ссылок собираются GC, и проблема смягчена. Но `Stop()` всё равно хорошая практика: так вы **явно освобождаете ресурсы сразу**, а не ждёте GC, и код работает правильно на любой версии.
- Тикер не останавливается сам, когда горутина завершилась. Если не вызвать `Stop`, он продолжит тикать впустую.
### Нюансы `Stop()`
- **`Stop()` не закрывает канал `C`.** Цикл `for range ticker.C` после `Stop` **повиснет навсегда**, а не завершится. Поэтому в `select` добавляют ветку `ctx.Done()` или канал завершения.
- Для **`Timer`** `Stop()` возвращает `true`, если таймер остановлен до срабатывания, и `false`, если уже сработал или был остановлен. До Go 1.23 при `false` нужно было вручную вычитать значение из `timer.C`, иначе `Reset` мог дать устаревший сигнал. С Go 1.23 канал таймера небуферизованный по поведению, и этот шаг не требуется.

### Ловушки

- **`time.Tick` и `time.After` в цикле/горячем пути**: создают новый таймер на каждый вызов (до Go 1.23 он жил до срабатывания). Для периодики используйте один `Ticker`, для сбрасываемого таймаута один `Timer` с `Reset`.
- **Медленный обработчик**: тики пропускаются, это нормально, но учитывайте при расчётах («раз в секунду» не гарантирует ровно N срабатываний).
- **Не забыть выход из цикла**: тикер без ветки отмены держит горутину вечно (утечка горутины).
- **Точность**: тик не строго по часам, зависит от планировщика и нагрузки.

### Коротко для собеседования

- **`Ticker`** периодически шлёт время в канал `C` (буфер 1, при медленном читателе тики **отбрасываются**), **`Timer`** срабатывает один раз, **`time.After`** это одноразовый таймер без возможности остановки.
- **`Stop()` нужен**, чтобы освободить ресурсы рантайма: до Go 1.23 неостановленный тикер не собирался GC (утечка), с 1.23 это смягчено, но `defer ticker.Stop()` остаётся правилом хорошего тона.
- `Stop` **не закрывает** `C`, поэтому для выхода из цикла нужна отдельная ветка (`ctx.Done()`).
