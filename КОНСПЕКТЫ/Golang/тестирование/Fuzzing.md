**Fuzzing** это автоматическая генерация случайных и мутированных входов для поиска ошибок, которые вы не предусмотрели в тестах: паники, зависания, нарушенные инварианты. Встроен в `go test`, управляется покрытием кода (coverage-guided): движок запоминает входы, открывающие новые ветки, и мутирует их.

```go
func FuzzReverse(f *testing.F) {
    // seed corpus: стартовые примеры
    f.Add("hello")
    f.Add("привет")
    f.Add("")

    f.Fuzz(func(t *testing.T, s string) {
        rev := Reverse(s)
        doubleRev := Reverse(rev)
        if s != doubleRev {
            t.Errorf("до: %q, после двойного разворота: %q", s, doubleRev)
        }
        if utf8.ValidString(s) && !utf8.ValidString(rev) {
            t.Errorf("Reverse породил невалидный UTF-8: %q", rev)
        }
    })
}
```

**Правила:**
- Функция называется `FuzzXxx(f *testing.F)`, внутри ровно один вызов `f.Fuzz`.
- `f.Add(...)` задаёт seed-корпус (можно и файлы в `testdata/fuzz/FuzzXxx/`).
- Параметры fuzz-функции (после `t`) могут быть только базовых типов: `string`, `[]byte`, `int*`, `uint*`, `float*`, `bool`, `rune`, `byte`.
- Нельзя полагаться на конкретный ответ, как в table-тесте. Проверяют **свойства (инварианты)**: «не паникует», «разбор и обратная сериализация дают исходное», «результат не длиннее входа», «два алгоритма дают одно и то же».


```bash
go test                              # обычный режим: прогоняет только seed-корпус и сохранённые падения
go test -fuzz=FuzzReverse            # режим fuzzing, работает пока не найдёт ошибку или не остановите
go test -fuzz=FuzzReverse -fuzztime=30s
go test -fuzz=FuzzReverse -fuzztime=10000x   # 10000 итераций
```

Найденный падающий вход автоматически сохраняется в `testdata/fuzz/FuzzReverse/<hash>`. Дальше он выполняется при **каждом обычном `go test`** как регрессионный тест, файл нужно закоммитить. Кэш генерируемого корпуса лежит в `$GOCACHE/fuzz`.

**Где полезен:** парсеры (JSON, форматы, протоколы), десериализация, валидаторы, всё, что принимает недоверенный ввод; функции с обратной операцией (encode/decode); сравнение с эталонной реализацией.

**Ограничения:**

- Функция должна быть быстрой и детерминированной, без глобального состояния и сетевых вызовов.
- Fuzzing не заменяет обычные тесты, а дополняет.
- В CI запускают короткие прогоны (`-fuzztime`) или только seed-корпус; длительный fuzzing гоняют отдельно.
