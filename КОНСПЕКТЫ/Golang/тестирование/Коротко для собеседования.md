- - **Тесты**: файлы `_test.go`, `TestXxx(t *testing.T)`. `Errorf` продолжает, `Fatalf` останавливает. **Table-driven**: слайс структур-случаев и цикл с `t.Run(name, ...)`, подтесты можно запускать выборочно и параллельно (`t.Parallel`). Полезны `t.Helper`, `t.Cleanup`, `t.TempDir`, `-race`, `-cover`.
- **Моки** работают через интерфейсы на стороне потребителя. Stub возвращает заготовленное, mock проверяет вызовы, fake это упрощённая реализация. **`testify`** даёт `assert`/`require` и `mock`; **`gomock`** (`go.uber.org/mock`) генерирует моки через `mockgen` с автопроверкой ожиданий. Мокайте границы системы и не привязывайте тесты к реализации.
- **Бенчмарки**: `BenchmarkXxx(b *testing.B)`, цикл по `b.N` (или `b.Loop()` с Go 1.24), запуск `go test -bench=. -benchmem`, сравнение через `benchstat`. **pprof**: CPU, heap, goroutine, block, mutex профили; снимаются из бенчмарка (`-cpuprofile`) или через `net/http/pprof`; анализ `go tool pprof -http=:8080`, `top`, flame graph. Сначала измерить, потом оптимизировать.
- **`go vet`** встроенный анализатор подозрительного кода (`Printf`, `copylocks`, `lostcancel`, `structtag`). **`golangci-lint`** запускает много линтеров сразу (`errcheck`, `staticcheck`, `gosec`, `revive`), настраивается `.golangci.yml`, обязателен в CI.
- **Fuzzing**: `FuzzXxx(f *testing.F)`, `f.Add` для seed, `f.Fuzz` с параметрами базовых типов; проверяются **инварианты**, а не конкретные ответы. Запуск `go test -fuzz=...`, найденные падения сохраняются в `testdata/fuzz` и становятся регрессионными тестами.
- **Build tags**: `//go:build linux && amd64` перед `package`, плюс суффиксы имён файлов (`_linux.go`), свои теги через `-tags`. **Cross-compilation**: `GOOS=linux GOARCH=amd64 go build`, для статического бинарника `CGO_ENABLED=0`, список платформ в `go tool dist list`.
