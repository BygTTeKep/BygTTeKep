**pprof** показывает, **где именно** тратятся время и память. Сначала измеряем, потом оптимизируем.

**Виды профилей:**

| Профиль                 | Что показывает                                   |
| ----------------------- | ------------------------------------------------ |
| CPU                     | на что уходит процессорное время                 |
| Heap (alloc/inuse)      | кто выделяет память и что сейчас занимает        |
| Goroutine               | стеки всех горутин (поиск утечек и deadlock)     |
| Block                   | где горутины ждут на каналах и мьютексах         |
| Mutex                   | конкуренция за мьютексы                          |
| Allocs                  | все аллокации с начала работы                    |
| Trace (`go tool trace`) | временная линия работы планировщика, GC, горутин |
**Из бенчмарка:**

```bash
go test -bench=. -cpuprofile=cpu.out -memprofile=mem.out
go tool pprof cpu.out
```
**Из работающего сервиса** (подключить пакет, он регистрирует эндпоинты в `init()` через blank import):

```go
import _ "net/http/pprof"

go func() {
    log.Println(http.ListenAndServe("localhost:6060", nil))
}()
```

```bash
go tool pprof http://localhost:6060/debug/pprof/profile?seconds=30   # CPU 30 с
go tool pprof http://localhost:6060/debug/pprof/heap
curl http://localhost:6060/debug/pprof/goroutine?debug=2             # дамп горутин
```

**Работа в интерактивном режиме `pprof`:**

```
(pprof) top          # самые тяжёлые функции
(pprof) top -cum     # по накопленному времени (с вызываемыми)
(pprof) list Func    # исходник функции с затратами по строкам
(pprof) web          # граф вызовов (нужен graphviz)
```

Веб-интерфейс: `go tool pprof -http=:8080 cpu.out` (граф, flame graph, таблицы).
В выводе `top`: **flat** это время в самой функции, **cum** с учётом всего, что она вызвала.

**Как читать:**

- Flame graph: ширина блока это доля времени, вершины широкие и плоские это горячие места.
- В heap-профиле смотрите `inuse_space` (что занято сейчас, поиск утечек) и `alloc_space` (кто больше всего выделяет, нагрузка на GC).
- Сравнение двух профилей: `go tool pprof -base old.out new.out`.

**Escape analysis** как дополнение к бенчмаркам: `go build -gcflags="-m"` показывает, какие переменные уходят в кучу.

**Типичный цикл оптимизации:** бенчмарк → профиль → правка узкого места → повторный бенчмарк → `benchstat` для сравнения. Также доступен **PGO** (profile-guided optimization, Go 1.21+): положите CPU-профиль продакшена как `default.pgo` в пакет `main`, и компилятор оптимизирует горячие пути (обычно выигрыш 2-14%).
