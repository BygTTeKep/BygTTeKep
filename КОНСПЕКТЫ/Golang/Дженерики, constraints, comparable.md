**Дженерики** (с Go 1.18) позволяют писать функции и типы, которые работают с разными типами, сохраняя проверку типов на этапе компиляции. Тип подставляется через **параметр типа** в квадратных скобках.

```go
func Map[T, U any](s []T, f func(T) U) []U {
    res := make([]U, 0, len(s))
    for _, v := range s {
        res = append(res, f(v))
    }
    return res
}

strs := Map([]int{1, 2, 3}, strconv.Itoa) // T=int, U=string выводятся автоматически
```

Дженерик-тип:
```go
type Stack[T any] struct {
    items []T
}

func (s *Stack[T]) Push(v T) { s.items = append(s.items, v) }
func (s *Stack[T]) Pop() (T, bool) {
    var zero T // zero value для T
    if len(s.items) == 0 {
        return zero, false
    }
    v := s.items[len(s.items)-1]
    s.items = s.items[:len(s.items)-1]
    return v, true
}

s := Stack[int]{}
```
Методы не могут иметь собственных параметров типа, только использовать параметры типа-владельца.

### Constraints (ограничения)

**Constraint** это интерфейс, который описывает, какие типы допустимы для параметра типа. От него зависит, какие операции можно делать со значениями `T`.
```go
func Sum[T int | float64](s []T) T {
    var total T
    for _, v := range s {
        total += v // + разрешён, потому что оба типа его поддерживают
    }
    return total
}
```

Ограничение можно вынести в интерфейс с **type set** (список типов через `|`):
```go
type Number interface {
    ~int | ~int64 | ~float32 | ~float64
}

func Max[T Number](a, b T) T {
    if a > b { return a }
    return b
}
```

**Тильда `~int`** означает «`int` и любой тип, чей базовый тип `int`». Без неё `type MyInt int` не подошёл бы:

Constraint может сочетать типы и методы:

```go
type StringableNumber interface {
    ~int | ~float64
    String() string
}
```

**Готовые constraints:**

- `any` без ограничений (алиас `interface{}`), можно только присваивать, передавать, хранить.
- `comparable` встроенный, типы, поддерживающие  сравнение и `!=`.
- Пакет `cmp`, `cmp.Ordered` (с Go 1.21): все типы с `<`, `>` (числа и строки).
- Пакет `golang.org/x/exp/constraints` (устаревает в пользу `cmp`): `Integer`, `Float`, `Signed`, `Unsigned`.
### comparable

`comparable` разрешает операторы сравнения и `!=`. Нужен, например, для ключей map:

```go
func Keys[K comparable, V any](m map[K]V) []K {
    res := make([]K, 0, len(m))
    for k := range m {
        res = append(res, k)
    }
    return res
}

func Index[T comparable](s []T, x T) int {
    for i, v := range s {
        if v == x { return i }
    }
    return -1
}
```

Что подходит: числа, строки, bool, указатели, каналы, массивы и структуры из comparable-полей. Слайсы, map и функции не подходят.

**Нюанс:** с Go 1.20 интерфейсные типы (например, `any`) тоже удовлетворяют `comparable`, но сравнение может вызвать панику в рантайме, если внутри лежит несравнимое значение (слайс). Для «строго comparable» такое не гарантируется.

### Вывод типов и явное указание

Обычно параметры выводятся из аргументов. Если вывести нельзя (например, тип встречается только в результате), указываем явно:

```go
func Zero[T any]() T { var z T; return z }
n := Zero[int]()
```

### Когда дженерики нужны

**Подходят:**

- **Универсальные структуры данных**: стек, очередь, set, кэш, связный список, LRU.
- **Функции над слайсами и map**, одинаковые для любого типа: `Map`, `Filter`, `Reduce`, `Contains`, `Keys`. Часть уже в стандартной библиотеке: пакеты `slices` и `maps` (с Go 1.21).
- **Одинаковая логика для разных числовых типов** (`Sum`, `Min`, `Max`; для последних в 1.21 есть встроенные `min` и `max`).
- Когда без них пришлось бы использовать `any` и type assertion (потеря типобезопасности) или копировать код.

**Не нужны:**

- Когда достаточно **интерфейса**. Если функции нужно только вызывать методы у значения, принимайте интерфейс. Например, `io.Reader` не нужно делать `[T io.Reader]`.
- Когда тип один, «на всякий случай».
- Когда логика различается для разных типов (тогда type switch или разные функции).
- В горячем коде без измерений: реализация использует **GC shape stenciling** (типы с одинаковой «формой» в памяти делят код, передавая словарь), поэтому производительность может отличаться от ручной специализации.

**Эвристика из документации Go:** сначала пишите обычный код, а дженерики добавляйте, когда видите, что копируете одну и ту же логику для разных типов.

### Ограничения

- Нельзя вызывать методы, которых нет в constraint (для `any` доступно ничего).
- Нельзя делать type switch по `T` напрямую, нужно привести к `any`: `switch any(v).(type)`.
- У методов нет своих параметров типа.
- Нельзя использовать параметр типа как embedded-поле.
- Для `any` нельзя сравнивать, для `comparable` нельзя `<`. Каждая операция требует подходящего constraint.

### Коротко для собеседования

- **Дженерики** дают типобезопасный переиспользуемый код через параметры типа `[T Constraint]`.
- **Constraint** это интерфейс со списком допустимых типов (`int | float64`) и/или методов, определяет, какие операции доступны. `~T` включает типы с базовым типом `T`.
- **`comparable`** разрешает сравнения и `!=`, нужен для ключей map и поиска. **`cmp.Ordered`** для `<` и `>`.
- Применять для контейнеров и универсальных функций над коллекциями, а если хватает интерфейса, дженерики не нужны.
