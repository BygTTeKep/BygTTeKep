Транзакции выполняют операцуции атомарно, либо все применяются (Commit), либо ни одна rollback

```go
tx, err := db.BeginTx(ctx, nil) // nil = опции по умолчанию
if err != nil {
    return err
}
```

`BeginTx` берёт из пула **одно соединение** и закрепляет за транзакцией до `Commit`/`Rollback`. Все запросы внутри нужно делать через `tx`, а не через `db`:
```go
_, err = tx.ExecContext(ctx, "UPDATE accounts SET balance = balance - $1 WHERE id = $2", amount, from)
```

Запрос через `db` пойдёт по другому соединению и в транзакцию не попадёт.
Опции: `&sql.TxOptions{Isolation: sql.LevelSerializable, ReadOnly: true}`.

Паттерн `defer tx.Rollback()`

```go
func transfer(ctx context.Context, db *sql.DB, from, to int, amount int64) error {
    tx, err := db.BeginTx(ctx, nil)
    if err != nil {
        return err
    }
    defer tx.Rollback() // безопасно вызывать после Commit

    if _, err := tx.ExecContext(ctx,
        "UPDATE accounts SET balance = balance - $1 WHERE id = $2", amount, from); err != nil {
        return err
    }
    if _, err := tx.ExecContext(ctx,
        "UPDATE accounts SET balance = balance + $1 WHERE id = $2", amount, to); err != nil {
        return err
    }

    return tx.Commit()
}
```

**Как это работает:**

- На любом раннем `return err` срабатывает отложенный `Rollback`, и транзакция откатывается, соединение возвращается в пул.
- После успешного `Commit` отложенный `Rollback` вернёт `sql.ErrTxDone` и **ничего не сделает**, поэтому его безопасно оставлять.
- Покрывает и панику: `defer` отработает, транзакция откатится.
- Исключает утечку соединения из-за забытого отката.

Ошибку `Rollback` в `defer` обычно игнорируют. Если нужно её залогировать, не считайте `ErrTxDone` ошибкой.

### Обёртка для переиспользования

```go
func WithTx(ctx context.Context, db *sql.DB, fn func(tx *sql.Tx) error) error {
    tx, err := db.BeginTx(ctx, nil)
    if err != nil {
        return err
    }
    defer tx.Rollback()

    if err := fn(tx); err != nil {
        return err
    }
    return tx.Commit()
}
```

### Контекст и транзакция
Если `ctx`, переданный в `BeginTx`, отменяется, транзакция **автоматически откатывается**. Поэтому используйте контекст запроса или с таймаутом, но не отменяйте его до `Commit`.

### Ловушки

- **Смешивание `db` и `tx`** внутри одной транзакции: часть операций окажется вне неё.
- **Забытый `Commit`/`Rollback`** держит соединение и блокировки в БД.
- **Долгие транзакции** держат блокировки и мешают другим. Не делайте внутри них HTTP-вызовы и другую медленную работу.
- **Вложенных транзакций нет.** Для частичного отката используют `SAVEPOINT` вручную.
- **Ошибка `Commit`** тоже должна обрабатываться (может не пройти из-за конфликта сериализации или обрыва): `return tx.Commit()`.
- **Параллельное использование одного `tx`** из разных горутин небезопасно: соединение одно, драйвер выполняет операции последовательно.
- **Дедлоки в БД**: если транзакции блокируют строки в разном порядке, БД прервёт одну из них. Блокируйте в едином порядке и предусмотрите повтор.
