Уровни абстракции от низкого к высокому:

```
pgx (родной драйвер) / database/sql  →  sqlx  →  query builders (squirrel, sqlc)  →  ORM (GORM, ent)
```

### `database/sql` (стандартная библиотека)

Универсальный интерфейс над любой БД. Многословный: ручной `Scan` в каждое поле, ручной цикл по `rows`. Зато минимум магии и зависимостей.

### `sqlx` (`github.com/jmoiron/sqlx`)

Тонкая надстройка над `database/sql`: **те же SQL-запросы**, но меньше шаблонного кода.

```go
type User struct {
    ID   int    `db:"id"`
    Name string `db:"name"`
}

var u User
err := db.GetContext(ctx, &u, "SELECT id, name FROM users WHERE id = $1", id)

var users []User
err = db.SelectContext(ctx, &users, "SELECT id, name FROM users WHERE age > $1", 18)

_, err = db.NamedExecContext(ctx,
    "INSERT INTO users (name, age) VALUES (:name, :age)", user)
```

- `Get` (одна строка) и `Select` (слайс) сами сканируют в структуры по тегам `db`.
- Именованные параметры (`:name`), помощник `sqlx.In` для `IN (...)`.
- Совместим с `database/sql`: `*sqlx.DB` встраивает `*sql.DB`.
- Остаётся «голый SQL», проверка запросов только в рантайме.
### `pgx` (`github.com/jackc/pgx/v5`)

Драйвер и набор инструментов **только для PostgreSQL**. Два режима:

1. **Родной API** (`pgxpool`) работает быстрее и умеет больше, чем `database/sql`.
2. **Адаптер `database/sql`** (`pgx/v5/stdlib`) для совместимости с остальным кодом.

```go
pool, err := pgxpool.New(ctx, dsn)

var name string
err = pool.QueryRow(ctx, "SELECT name FROM users WHERE id = $1", id).Scan(&name)
if errors.Is(err, pgx.ErrNoRows) { ... }
```

Возможности родного API: `COPY` (быстрая массовая вставка), `LISTEN/NOTIFY`, батчи запросов (`pgx.Batch`), нативная работа с типами Postgres (массивы, JSONB, `uuid`, `hstore`), `CollectRows` / `RowToStructByName` для сканирования в структуры.

Минус: привязка к PostgreSQL. Сегодня это де-факто стандартный драйвер для Postgres (старый `lib/pq` в режиме поддержки).

### Плюсы и минусы ORM

**Плюсы:**

- Меньше шаблонного кода для CRUD.
- Быстрый старт и прототипирование.
- Работа со связями и загрузка вложенных объектов.
- Переносимость между СУБД (на практике ограниченная).
- Встроенные хуки, мягкое удаление, миграции.

**Минусы:**

- **Скрытый SQL**: сложно понять, какие запросы реально выполняются, легко получить **N+1** (запрос на каждый элемент списка) или лишние `SELECT *`.
- **Производительность**: рефлексия, лишние аллокации; сложные запросы часто неэффективны.
- **Магия**: неочевидное поведение (`Save` обновляет все поля, `Update` с нулевыми значениями игнорирует их в структуре, `First` добавляет `ORDER BY` и `LIMIT`).
- **Сложные запросы** (оконные функции, CTE, специфичные возможности СУБД) всё равно приходится писать сырым SQL.
- Привязка к API библиотеки, сложнее отлаживать, труднее оптимизировать узкие места.
- `AutoMigrate` не подходит для продакшена (не удаляет колонки, нет версионирования, нет отката).

**Практика:** для простых CRUD-сервисов ORM ускоряет разработку; для высоконагруженных и сложных по запросам систем чаще берут `pgx` + `sqlx`/`sqlc` и пишут SQL вручную. Часто комбинируют.
