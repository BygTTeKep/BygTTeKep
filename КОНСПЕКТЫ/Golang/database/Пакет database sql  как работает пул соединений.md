sql.DB - Это не соединение, а потокобезопасныйй пул соединений, его создают один раз на приложение и используют из всех горутин. Конкретная база подключается через драйвер
```go
import (
    "database/sql"
    _ "github.com/jackc/pgx/v5/stdlib" // драйвер регистрируется в init()
)

db, err := sql.Open("pgx", dsn) // соединение НЕ устанавливается
if err != nil {
    return err
}
defer db.Close()

if err := db.PingContext(ctx); err != nil { // реальная проверка соединения
    return err
}
```
sql.Open только проверяет аргументы и создает пул. Соединения открываются лениво. Чтобы проверить доступность бд на старте нуден Ping

# Как работает пул соединений
Когда вызывается db.QueryContext()
1) Пул берет свободное соединение
2) Если нет свободного соединения но лимит не достигнут создается нвоое
3) Если лимит достигнут, запрос ждет пока соединение освободиться или истечет ctx
4) После завершения запроса, соединение возрашается в пул(не закрывается)
### Настройки пула

```go
db.SetMaxOpenConns(25)                  // максимум открытых соединений (по умолчанию 0 = без лимита)
db.SetMaxIdleConns(25)                  // максимум простаивающих в пуле (по умолчанию 2)
db.SetConnMaxLifetime(30 * time.Minute) // максимальное время жизни соединения
db.SetConnMaxIdleTime(5 * time.Minute)  // сколько соединение может простаивать
```

- **`MaxOpenConns`**: защита БД от перегрузки. Без лимита под нагрузкой можно упереться в `max_connections` сервера. Обычно задают явно.
- **`MaxIdleConns`**: слишком маленькое значение приводит к постоянному закрытию и открытию соединений. Обычно делают равным `MaxOpenConns`. Если `MaxIdle > MaxOpen`, оно урезается до `MaxOpen`.
- **`ConnMaxLifetime`**: нужен, чтобы соединения периодически обновлялись (балансировщики, failover, прокси рвут старые соединения).
- **`ConnMaxIdleTime`**: освобождает ресурсы в периоды простоя.
### Ловушки
- **Утечка соединений.** Соединение возвращается в пул только после закрытия `Rows` (или полного чтения). Забытый `rows.Close()` держит соединение навсегда, и пул быстро исчерпывается.
- **Незавершённая транзакция** тоже держит соединение.
- Создавать `sql.DB` на каждый запрос нельзя: теряется смысл пула.
- Отдельные запросы подряд **могут идти по разным соединениям**. Состояние сессии (`SET`, временные таблицы, advisory locks) между вызовами не сохраняется. Для этого есть `db.Conn(ctx)` (закреплённое соединение) или транзакция.
