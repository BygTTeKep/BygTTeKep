## struct, embedding, композиция вместо наследования
**Struct** это составной тип, набор именованных полей. Это значение: при присваивании и передаче копируется целиком. Zero value: все поля в своих zero value.

структуры можно сравнивать == если все поля comparable, можно использовать как ключ дляч map
**Анонимная структура**: `point := struct{ X, Y int }{1, 2}`. Удобна в тестах (table-driven) и для одноразовых данных.
Методы объявляются отдельно от структуры (`func (u User) ...`), в самом `struct` их нет.
Порядок полей влияет на размер из-за **выравнивания (padding)**: `bool, int64, bool` займёт больше, чем `int64, bool, bool`.

### Embedding (встраивание)

Если в структуре указать тип **без имени поля**, он встраивается. Его поля и методы «продвигаются» (promoted) на внешний тип.
```go
type Animal struct {
    Name string
}

func (a Animal) Speak() string { return a.Name + " makes a sound" }

type Dog struct {
    Animal        // встраивание
    Breed string
}

d := Dog{Animal: Animal{Name: "Rex"}, Breed: "Lab"}
fmt.Println(d.Name)    // Rex, поле продвинуто
fmt.Println(d.Speak()) // Rex makes a sound, метод продвинут
fmt.Println(d.Animal.Name) // явный доступ тоже работает
```
**Переопределение (shadowing).** Внешний тип может определить метод с тем же именем. Он скроет продвинутый, но встроенный остаётся доступен явно:
```go
func (d Dog) Speak() string {
    return d.Animal.Speak() + " (woof)"
}
```

встраивание интерфейса в структуру позволяет **частично реализовать** интерфейс (например, в моках переопределить один метод, остальные делегируются встроенному значению).

**Встраивание указателя:** `*Animal`. Тогда встроенный объект может быть nil (обращение к его полям вызовет панику), зато его можно разделять между структурами.

**Конфликты имён.** Если два встроенных типа на одном уровне имеют одно и то же имя поля или метода, обращение по короткому имени даёт ошибку компиляции (ambiguous selector). Нужно указывать явно: `d.A.Name`.

**Ловушки:**
- Встроенный `sync.Mutex` делает `Lock`/`Unlock` публичными методами внешнего типа, чаще лучше держать его приватным полем (`mu sync.Mutex`).
- При встраивании типа с методом `String()` или `MarshalJSON()` он продвигается и **меняет поведение внешнего типа** (например, `json.Marshal` вызовет чужой `MarshalJSON` для всей структуры).
- Встроенный тип и в JSON «раскрывается» в плоскую структуру, если у него нет тега.
### Композиция вместо наследования

В Go **нет наследования** классов: нет `extends`, нет иерархий, нет `super`. Встраивание это не наследование, а **автоматическое делегирование**:

- `Dog` **не является** `Animal` (нельзя передать `Dog` туда, где ожидается `Animal`). Полиморфизм в Go обеспечивают **интерфейсы**.
- Метод встроенного типа работает с **встроенным** значением, а не с внешним. Виртуальных методов нет: если `Animal.Speak()` внутри вызывает `a.Sound()`, он вызовет `Animal.Sound()`, а не переопределённый в `Dog`.

**Принцип:** строим сложные типы из простых частей (has-a), а поведение описываем маленькими интерфейсами. Это даёт слабую связанность, простое тестирование (подмена зависимостей через интерфейсы) и отсутствие хрупких иерархий.

**Композиция без встраивания:** иногда лучше именованное поле (`logger Logger`), чем встраивание, чтобы не раскрывать методы внутреннего типа наружу.
