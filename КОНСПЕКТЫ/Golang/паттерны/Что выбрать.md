### Что выбрать

|Задача|Паттерн|
|---|---|
|Обработать много задач ограниченным числом горутин|Worker pool (или `errgroup` + `SetLimit`)|
|Ускорить одну стадию, раздав работу нескольким горутинам|Fan-out|
|Собрать результаты из нескольких источников в один поток|Fan-in|
|Многостадийная обработка потока данных|Pipeline|
|Ограничить конкурентный доступ к ресурсу|Semaphore|

### Типичные ошибки во всех паттернах

- **Забыли закрыть канал**: `range` у потребителя висит вечно.
- **Закрыли канал не владелец** или несколько раз: паника.
- **Нет `ctx.Done()` при отправке/получении**: утечки горутин при раннем выходе.
- **Ожидание порядка** там, где его нет (воркеры и fan-in возвращают в произвольном порядке).
- **Захват переменной цикла** до Go 1.22.
- **Паника в воркере** роняет процесс: ставьте `recover` внутри горутины.
- **Лишняя сложность**: для небольшой задачи хватит `WaitGroup` или `errgroup`.

### Коротко для собеседования

- **Worker pool**: N воркеров читают общий канал задач; канал задач закрывает продюсер, канал результатов закрывается после `wg.Wait()`.
- **Fan-out**: несколько горутин читают один канал. **Fan-in**: несколько каналов сливаются в один (горутина на источник + `WaitGroup` для закрытия).
- **Pipeline**: цепочка стадий `<-chan T → <-chan U`, каждая закрывает свой выход, везде `ctx` для отмены.
- **Semaphore**: `chan struct{}` с ёмкостью N или `x/sync/semaphore`; занять слот перед запуском, освободить через `defer`.
