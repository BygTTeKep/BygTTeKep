## Что можно и нельзя хранить в `WithValue`

`WithValue` предназначен для **данных, привязанных к запросу и пересекающих границы API** (процессов, библиотек, middleware), а **не** для передачи обычных параметров функций.

**Можно:**

- request ID, trace ID / span, correlation ID;
- данные аутентификации (ID пользователя, роли), полученные в middleware;
- информацию, нужную транзитом, через слои, которые сами её не используют (логгер с полями запроса, локаль).

**Нельзя (плохая практика):**

- **Опциональные параметры функций и зависимости**: конфиг, подключение к БД, кэш, сервисы. Они делают зависимости неявными, теряется проверка типов, код сложнее читать и тестировать. Передавайте через аргументы или поля структур.
- **Большие объёмы данных.** Значения ищутся по цепочке линейно, каждое `WithValue` это ещё один узел.
- **Изменяемые данные без синхронизации**: контекст делят горутины.

### Ключи

Ключ должен быть **собственным неэкспортируемым типом**, иначе разные пакеты могут случайно перезаписать значения друг друга (ключ сравнивается по типу и значению):

```go
type ctxKey struct{}          // приватный тип ключа

func WithRequestID(ctx context.Context, id string) context.Context {
    return context.WithValue(ctx, ctxKey{}, id)
}

func RequestID(ctx context.Context) (string, bool) {
    id, ok := ctx.Value(ctxKey{}).(string)
    return id, ok
}
```

Плохо: `context.WithValue(ctx, "requestID", id)`: строка как ключ может конфликтовать с чужим кодом (`go vet` предупредит).

**Практика:** прячьте ключ за парой функций-обёрток (`WithX` / `X`), как выше. Значения **неизменяемы**: `WithValue` не меняет родителя, а возвращает новый контекст.
