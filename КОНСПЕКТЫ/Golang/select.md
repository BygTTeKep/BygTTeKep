select позволяет горутине ждать выполнение операций сразу с несколькими каналами и выполнить ту которая готова первой
```go
select {
case v := <-ch1:
    fmt.Println("получили из ch1:", v)
case ch2 <- 42:
    fmt.Println("отправили в ch2")
case <-done:
    return
}
```
### Как работает

1. Все выражения каналов и отправляемые значения вычисляются **один раз**, в порядке записи, при входе в `select`.
2. Если **готова ровно одна** ветка, выполняется она.
3. Если готовы **несколько**, выбирается **случайная** (псевдослучайно, равномерно). Приоритета по порядку записи нет, это защита от голодания.
4. Если **не готова ни одна** и нет `default`, горутина **блокируется**, пока какая-то не станет готовой.
5. Пустой `select {}` блокируется навсегда (иногда используют, чтобы `main` не завершался).
Готовность: получение готово, если в канале есть значение или он закрыт; отправка готова, если есть ожидающий получатель или место в буфере. **Отправка в закрытый канал внутри `select` вызывает панику**, как и вне него.

### `default`: неблокирующие операции

Ветка `default` выполняется, **если ни одна другая ветка не готова**. Тогда `select` не блокируется.

```go
// неблокирующее получение
select {
case v := <-ch:
    fmt.Println("есть значение", v)
default:
    fmt.Println("пока пусто")
}

// неблокирующая отправка
select {
case ch <- v:
default:
    fmt.Println("канал занят, пропускаем")
}
```

Применение: попытка отправить без ожидания (сбросить значение, если потребитель не успевает), проверка отмены без остановки работы.

```go
for {
    select {
    case <-ctx.Done():
        return
    default:
    }
    doWork() // продолжаем, если не отменено
}
```

**Ловушка: busy loop.** `select` с `default` внутри цикла без пауз крутится на 100% CPU:

```go
for {
    select {
    case v := <-ch:
        handle(v)
    default: // ветка срабатывает мгновенно, цикл не ждёт
    }
}
```

Если нужно ждать, `default` убирают и позволяют `select` блокироваться.

### Таймауты

Каналы + время дают таймаут без специальных механизмов.

**`time.After`**: возвращает канал, в который через заданное время придёт значение.

```go
select {
case res := <-resultCh:
    fmt.Println("результат:", res)
case <-time.After(2 * time.Second):
    fmt.Println("таймаут")
}
```

**Предпочтительный способ: `context`.**

```go
ctx, cancel := context.WithTimeout(ctx, 2*time.Second)
defer cancel()

select {
case res := <-resultCh:
    return res, nil
case <-ctx.Done():
    return nil, ctx.Err() // context.DeadlineExceeded
}
```

Контекст пробрасывается вглубь вызовов и отменяет всё дерево, а не только одно ожидание.

### `time.After` в цикле

В Go до 1.23 каждый вызов `time.After` создаёт таймер, который **не освобождался до срабатывания**, даже если `select` уже выбрал другую ветку. В горячем цикле это накапливало мусор и расход памяти.

```go
for {
    select {
    case v := <-ch:
        handle(v)
    case <-time.After(time.Second): // новый таймер на каждой итерации
        return
    }
}
```

С Go 1.23 неиспользуемые таймеры собираются GC, и проблема сильно смягчена (при `go 1.23` и выше в `go.mod`). В старых версиях и для явного контроля используют один `time.Timer` с `Reset` либо `context`:

```go
t := time.NewTimer(time.Second)
defer t.Stop()
for {
    select {
    case v := <-ch:
        handle(v)
        if !t.Stop() { select { case <-t.C: default: } } // сброс по правилам старых версий
        t.Reset(time.Second)
    case <-t.C:
        return
    }
}
```

### Типичные паттерны

**Отмена + работа:**

```go
for {
    select {
    case <-ctx.Done():
        return ctx.Err()
    case job, ok := <-jobs:
        if !ok {
            return nil // канал закрыт
        }
        process(job)
    }
}
```

**Периодические задачи:** `time.Ticker` в одной из веток.

```go
ticker := time.NewTicker(time.Second)
defer ticker.Stop()
for {
    select {
    case <-ticker.C:
        tick()
    case <-ctx.Done():
        return
    }
}
```

**Отключение ветки через nil-канал.** Операции с `nil`-каналом блокируются навсегда, значит такая ветка не выбирается:

```go
for a != nil || b != nil {
    select {
    case v, ok := <-a:
        if !ok { a = nil; continue } // канал закрыт, отключаем ветку
        out <- v
    case v, ok := <-b:
        if !ok { b = nil; continue }
        out <- v
    }
}
```

Так сливают несколько каналов (merge), не зацикливаясь на закрытых.

**Приоритет вручную.** Случайность выбора означает, что приоритет задать нельзя напрямую. Обходной путь: сначала неблокирующая проверка приоритетного канала, затем общий `select`.

```go
select {
case <-ctx.Done():
    return
default:
}
select {
case <-ctx.Done():
    return
case v := <-ch:
    handle(v)
}
```

### Ловушки

- **`break` внутри `select`** выходит только из `select`, а не из внешнего `for`. Для выхода из цикла используют `return`, метку (`break loop`) или флаг.
- **Закрытый канал в `select`** всегда готов, поэтому цикл с ним без отключения ветки крутится вхолостую (см. nil-канал выше).
- **`default` делает `select` неблокирующим**, что почти всегда нужно осознанно.
- **Утечка горутины:** отправитель в ветке `select` без `ctx.Done()` может навсегда зависнуть, если получателя нет.
- **Порядок веток не задаёт приоритет.** Выбор случаен.

### Коротко для собеседования

- **`select`** ждёт несколько операций с каналами и выполняет готовую; при нескольких готовых выбирает **случайную**, при отсутствии готовых блокируется.
- **`default`** срабатывает, когда ничего не готово, и делает операцию неблокирующей. В цикле без пауз даёт busy loop.
- **Таймаут:** ветка `<-time.After(d)` или, лучше, `<-ctx.Done()` с `context.WithTimeout`. `time.After` в цикле создаёт таймер на каждую итерацию (до Go 1.23 это утечка до срабатывания).
- **`nil`-канал** в `select` отключает ветку, **закрытый** канал всегда готов, `break` выходит только из `select`.
