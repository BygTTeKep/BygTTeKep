Мьютекс «много читателей или один писатель».

- `RLock()` / `RUnlock()`: сколько угодно читателей одновременно
- `Lock()` / `Unlock()`: эксклюзивный доступ, блокирует и читателей, и писателей

```go
type Cache struct {
    mu sync.RWMutex
    m  map[string]string
}

func (c *Cache) Get(k string) (string, bool) {
    c.mu.RLock()
    defer c.mu.RUnlock()
    v, ok := c.m[k]
    return v, ok
}

func (c *Cache) Set(k, v string) {
    c.mu.Lock()
    defer c.mu.Unlock()
    c.m[k] = v
}
```

**Когда выигрывает:** читают значительно чаще, чем пишут, а критическая секция читателя нетривиальна. При коротких секциях или частых записях обычный `Mutex` часто **быстрее**, потому что `RWMutex` дороже по накладным расходам.

**Ловушки:**

- **Нельзя повышать `RLock` до `Lock`**: взять `Lock`, не отпустив `RLock`, это deadlock.
- **Рекурсивный `RLock`** опасен: если между двумя `RLock` одной горутины писатель вызвал `Lock`, новые читатели блокируются, и получается deadlock. Ожидающий писатель блокирует новых читателей (защита от голодания писателей).
- Писать под `RLock` нельзя (data race).
