Атомики - это примитив из пакет sync/atomic, которые позволяют безопасно работать с переменными из нескольких горутин без Mutex.

Пакет **`sync/atomic`** даёт неделимые (атомарные) операции над числами и указателями. Они выполняются целиком, без блокировок, на уровне инструкций процессора. Подходят для простых счётчиков и флагов, где мьютекс избыточен.

Ключевое свойство - операции выполняются неделимо. Это означает что ни одна другая горутина не увидет промежуточное состояние операции.

Проблема которую решают атомики - race condititon.

Атомики работают только с простыми операциями.

Основные операции
```go
var p int64 = 0
atomic.AddInt64(&p, 1) //атомарное увеличение 
atomic.AddInt64(&p, -1) //атомарное уменьшение
atomic.LoadInt64(&p) // атомарное чтение
atomic.StoreInt64() //атомарная запись
CAS

```

Доступны: `atomic.Int32`, `Int64`, `Uint32`, `Uint64`, `Uintptr`, `Bool`, `Pointer[T]`, `Value`. С Go 1.23 у целых типов есть `And` и `Or` (побитовые операции).

### Функциональный стиль (старый)

```go
var n int64
atomic.AddInt64(&n, 1)
atomic.LoadInt64(&n)
atomic.CompareAndSwapInt64(&n, 0, 1)
```

Типы-обёртки лучше: нельзя случайно прочитать переменную без `atomic` и они гарантируют выравнивание (на 32-битных платформах `int64` в функциональном стиле должен быть выровнен по 8 байт).

### CAS (Compare-And-Swap)

Основа lock-free алгоритмов: «если значение сейчас равно `old`, заменить на `new`, вернуть успех».

```go
for {
    old := v.Load()
    if v.CompareAndSwap(old, old*2) {
        break
    }
    // кто-то изменил значение, повторяем
}
```

### `atomic.Value` и `atomic.Pointer[T]`

Атомарная замена целого объекта (например, конфигурации). Читатели без блокировок всегда видят цельную версию:

```go
var cfg atomic.Pointer[Config]

cfg.Store(&Config{...})   // обновление
c := cfg.Load()           // чтение; объект после Store менять нельзя
```

Паттерн **copy-on-write**: создаём новый объект, меняем указатель, старый не трогаем. `atomic.Value` хранит `any`, тип при всех `Store` должен быть одинаковым, иначе паника, и `nil` хранить нельзя.

### Когда atomic, когда mutex

**Atomic:** один счётчик, флаг, указатель на неизменяемый снимок.  
**Mutex:** нужно изменять несколько связанных полей согласованно, выполнять составные операции (прочитать, проверить, записать), защищать map/slice.

Две отдельные атомарные операции вместе атомарными **не являются**:

```go
if flag.Load() { flag.Store(false) } // между Load и Store может вклиниться другая горутина
```

Для такого случая нужен `CompareAndSwap`.

Атомарные операции также гарантируют **порядок видимости** (happens-before): запись через `atomic.Store` и чтение этого значения через `Load` синхронизируют горутины.
