**Идея:** функции и конструкторы **принимают** интерфейсы в параметрах и **возвращают** конкретные типы.

```go
// принимаем интерфейс, возвращаем конкретную структуру
func NewService(store UserStore, log Logger) *Service {
    return &Service{store: store, log: log}
}
```

### Почему принимать интерфейсы

- **Гибкость для вызывающего:** передать можно что угодно с нужными методами (реальную реализацию, fake, мок).
- **Тестируемость:** зависимость легко подменить.
- **Минимальные требования:** функция заявляет, что ей нужно, и не больше. Например, `io.Reader` вместо `*os.File` позволяет читать из файла, сети, буфера, строки.

```go
func Parse(r io.Reader) (*Config, error) // работает с чем угодно, что читается
```

### Почему возвращать структуры

- **Вызывающий получает всё:** все поля и методы конкретного типа, а не урезанный интерфейс.
- **Можно добавлять методы без поломки API.** Если вернуть интерфейс, новый метод в нём ломает все чужие реализации. Новый метод у структуры никого не ломает.
- **Интерфейс определяет потребитель** (см. ниже), а не автор типа. Вернув интерфейс, вы навязываете абстракцию, которая может не подойти.
- Меньше косвенности, проще навигация по коду (переход к определению ведёт в реальную реализацию), а компилятор лучше оптимизирует.
- Нет ловушки с nil: возврат `*MyErr` как `error` или `*T` как интерфейса даёт интерфейс с типизированным nil.

### Исключения

Возвращать интерфейс нормально, когда:

- **Реализаций несколько, и вызывающему не важно, какая:** `errors.New` возвращает `error`, `context.WithCancel` возвращает `Context`, `sha256.New()` возвращает `hash.Hash`.
- Тип намеренно скрыт (приватная реализация, публичный контракт).
- Фабрика выбирает реализацию на основе параметров.

### Ловушки

- **Не создавайте интерфейс «на всякий случай»** с единственной реализацией: это лишний слой. Интерфейс появляется, когда есть реальная потребность (две реализации или нужна подмена в тестах).
- Принимайте **минимально нужный** интерфейс. Не `*sql.DB`, если нужен только один метод `QueryRowContext`.
- Это правило-ориентир, а не закон.
