### Sentinel-ошибки

**Sentinel** это заранее объявленная переменная-ошибка, с которой сравнивают:

```go
var ErrNotFound = errors.New("not found")

// проверка
if errors.Is(err, ErrNotFound) { ... }
```

Примеры из стандартной библиотеки: `io.EOF`, `sql.ErrNoRows`, `os.ErrNotExist`, `context.Canceled`.

**Плюсы:** просто, легко проверять, не нужен новый тип.  
**Минусы:** нет дополнительных данных; переменная становится частью публичного API пакета; она изменяема (теоретически кто-то может её переприсвоить, поэтому называют с префиксом `Err`, и не трогают).

### Кастомные типы

Нужны, когда вызывающему требуются **детали**: поле, код, ID, признак «можно повторить».

```go
type HTTPError struct {
    Code int
    Msg  string
}
func (e *HTTPError) Error() string { return fmt.Sprintf("http %d: %s", e.Code, e.Msg) }

var he *HTTPError
if errors.As(err, &he) && he.Code == 404 { ... }
```

**Плюсы:** можно нести структурированные данные, проверять через `errors.As`.  
**Минусы:** больше кода, тип тоже становится частью API.

### Когда что

|Ситуация|Что выбрать|
|---|---|
|Вызывающему нужно только знать «что случилось» (не найдено, конец данных)|Sentinel|
|Нужны детали (поле, код, причина)|Кастомный тип|
|Ошибка только для лога, никто не будет её проверять|Просто `fmt.Errorf`|

**Практические советы:**

- Проверяйте через `errors.Is` / `errors.As`, а не через оператор сравнения и type assertion, чтобы работать с обёрнутыми ошибками.
- Не делайте публичными ошибки, на которые вызывающий не должен опираться. Обёртывая через `%w`, вы делаете исходную ошибку частью контракта; если не хотите этого, используйте `%v`.
- Часто делают ошибку-«категорию» и оборачивают её конкретикой: `fmt.Errorf("user %d: %w", id, ErrNotFound)`.
- Ошибки предметной области (`ErrNotFound`) лучше не привязывать к деталям инфраструктуры: на границе слоя конвертируйте `sql.ErrNoRows` в свою `ErrNotFound`.
